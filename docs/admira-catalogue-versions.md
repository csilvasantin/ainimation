# Edit an Admira catalogue asset and save a linked version

Stock opens `studio.html` for Director or `interactivos/` for structured interactive projects. The existing `admiraStock*` parameters carry the source asset. `admiraEditable=director|interactive` requests its saved source from `https://api.admira.store/stock/editor-project/:id`. `admiraReturnUrl` preserves the catalogue host, language and client filter; only the public Admira/Pixeria Stock paths are accepted.

A new publication sends an `ainimation.editor.v1` envelope (`kind`, `plan`) as `editorProject` to `/stock/publish`, together with the rendered WebM or interactive HTML. `externalRef` identifies the immediate parent. The Stock service validates that parent, writes a new asset and immutable source, and returns `editorProjectUrl`, `versionRoot`, `id` and the index receipt. The editable source is separate from the catalogue index. Matching rendered bytes must not collapse distinct editable versions or steal the original asset's hash mapping.

Only after successful confirmation does the editor return to `?highlight=<new-id>&origen=<root-id>`. On error the editor and local project remain available. If further edits occurred during upload, the editor displays a link to the saved revision and preserves the newer work.

Director preserves the previous workspace in `ainimation:before-admira-edit`. On reopen, query parameters are removed after the source is saved locally, so reload does not discard subsequent edits. Structured interactives open as a new local library entry and preserve existing projects. Blob media is embedded into a portable source; the source has a 24 MiB limit.

Older rendered videos open as a new single-media composition. Older HTML interactives without editable source cannot reconstruct their original layers or behaviours; the editor explains that their original project must be imported. New interactive publications retain both their HTML and their editable source.

Release order: deploy the Stock service from the matching pixer-worker change, publish this editor, then merge the Pixeria catalogue change and regenerate admira.studio through its existing mirror process. Do not edit the generated mirror manually. No migration or replacement of existing assets is required.

Validation includes the Stock handler with an in-memory R2 bucket, editor source and return-link tests, catalogue descendant/link tests in ES and EN, and a Chrome headless check editing and publishing a video and structured interactive before returning to the catalogue.

## Create from multiple catalogue resources

The catalogue's selection bar opens **Create in AInimation** with the selected items in selection order. The user chooses a title, landscape/portrait/square format, and video or interactive output. Both open Director; interactive output retains Director's buttons and behaviours and exports HTML. This flow does not import these materials into the separate structured interactive creator.

The shared `assets/admira-resource-batch.mjs` contract accepts 1–20 HTTPS image, video and audio references in a bounded `admiraBatch` URL fragment. HTML projects and other unsupported types fail the whole selection with an explanation. No binary data or credentials are copied into the URL. The editor validates the whole batch before changing its workspace, preserves the previous project in `ainimation:before-admira-create`, and offers a recovery button in Cast, including after reload. Reload does not reimport the original selection over edits.

Visuals form a sequence (four seconds when duration is unknown); soundtracks start at frame one. The user can adjust timing and add interactions in Director. Audio controls in the HTML runtime require a user gesture to start sound under browser autoplay rules. Audio's editing glyph is excluded from the rendered video.

The new plan retains every input in `admiraSources`. It has catalogue return context but no immediate-parent ID: a composition of several inputs is a new work, not a revision of one arbitrarily chosen resource. The existing save/return integration preserves the editable source, sends the correct WebM/HTML MIME, and highlights the newly saved work.

Release: publish AInimation before enabling the catalogue action. Publish Pixeria next, then apply only this release's catalogue delta and its two new modules through Studio's scoped generator. Do not run a full Studio mirror sync, which would remove independent Studio features. No Worker change is required.

Validation: 241 editor unit tests pass. Chrome headless exercises ES/EN selection of image/video/audio, both outputs, selection order, format, workspace recovery, reload, HTML with all three media, and intercepted save/return with all input IDs. The video recording is stubbed in that integration test; rendering real video and production saves remain release checks. No production data is written by the preparation tests.

## Preview and check before publishing

Director's **Previsualizar y comprobar para Admira** entry and its existing Stock save action share one pre-publication review. The structured interactive creator uses the same review before its catalogue save. The older interactive ZIP/Stock route also checks before its Stock request. Local-only ZIP export remains available independently.

The review offers horizontal (1920×1080), vertical (1080×1920), and touch-screen (768×1024) viewports without changing the authored Stage format. Video preview plays the exact recorded Blob later uploaded; it is not recorded again after confirmation. Interactive preview runs the HTML that will be published inside a sandboxed frame. The preview adds only error monitoring; that monitoring is not included in the published artifact. External windows, navigation outside the frame, forms and same-origin storage are restricted in preview, so this is a local interaction test rather than a test of payments or external services.

Before enabling publication, media is loaded with a ten-second timeout and anonymous CORS, with at most four concurrent probes. Missing/undecodable resources block publication; the source remains editable. Enabled Director rules are checked against the actions and conditions actually implemented by the player; marker, sprite and sound references are checked. Admingo scripts are compiled for syntax errors. The structured creator checks scene and hotspot destinations. Small touch controls and the limits of script-path verification appear as warnings. The author confirms that they have reviewed the video or exercised the required interactions; static analysis does not establish that every behaviour is correct.

A failed player build (including a missing runtime) or a runtime error reported by the sandbox blocks confirmation. A changed workspace invalidates the frozen review. Cancel returns to editing without making a publication request. Upload progress is shown in the review; a failed save retains the editor and offers a return to editing for a fresh review and retry. New sources, version relationships, and save/return context keep the existing catalogue contract.

Validation: 247 editor unit tests pass, including six new preflight cases. Chrome headless covers all preview modes; cancellation with zero posts and abortion of an actual recorder; stale workspace rejection; broken resources before recording; failed save and successful retry; real Director touch navigation; a missing runtime; a runtime exception inside the isolated frame; and structured interactive navigation plus save/return. These checks use intercepted publication requests and a short generated WebM for video preview; production publication is not part of preparation.

Release requires only this AInimation editor change. No Stock, Pixeria or Studio mirror change is needed: the existing catalogue destinations open the updated editor. Production validation should exercise the review and actual publication of a temporary video and interactive and remove those pieces afterwards.

Run the reproducible headless review checks with `npm run verify:admira-review` after installing Playwright and its browser. To use installed Chrome, set `PLAYWRIGHT_BROWSER_CHANNEL=chrome`. Screenshots go to `/tmp/ainimation-preflight-qa` by default (`PREFLIGHT_ARTIFACT_DIR` overrides it). Publication requests are intercepted.

## Compare and replace linked resource versions

Director's **Archivo → Actualizar recursos de Admira…** opens a comparison for the Stock resources already used in the creation. It reads the complete public index with a fresh request, rather than the `/stock/list` route's 200-item cap. Version relationships come from explicit `externalRef`/`versionRoot` links. No title matching is used. Compatible linked descendants and newer sibling branches are offered; ancestors and versions known to be older than the current one are excluded. An unspecified date is shown explicitly. HTML projects and changes of media type are not replacements for image/video/audio inputs.

The dialog shows current and selected media side by side, their identifiers, available dimensions/duration, the number of usages, and the montage values that will be retained. Nothing is selected by default. Every usage of the chosen input is updated, preserving its own position, size, rotation, opacity, keyframes, start and duration. Names and sprite IDs, rules, scripts, markers and the composition's parent/return context remain unchanged. Only source URLs, Stock identity and source-media metadata are replaced. `admiraSources` is updated to the selected identities. A shorter source clip produces a warning; its existing Timeline duration is not changed.

Selected new media must load/decode through the existing media probe before the whole operation is committed. A failed resource, changed workspace or unavailable backup storage blocks the operation. The previous plan and committed result are stored under `ainimation:before-admira-resource-update`; **Deshacer sustitución** in Cast and **Archivo → Deshacer última sustitución de recursos** can restore it, including after reload. Direct restoration refuses to overwrite subsequent edits or another project; the regular Edit history remains available for later work. No catalogue asset is written by substitution; a later reviewed publication creates the usual new editable composition version.

Current imports now retain explicit Stock IDs. Older projects can also resolve canonical API/R2 asset paths or uniquely linked provenance. Material whose identity cannot be verified is reported without guessing a relationship. The complete comparison is frozen while open, and selection is checked again after loading media before applying it.

Seven headless browser scenarios cover comparison/cancel, image/video/audio substitution and reload, a sound action using the updated audio, undo, broken new media, later edits and an unavailable catalogue. ## Publish a package of horizontal, vertical and touch versions

**Archivo → Preparar paquete horizontal, vertical y táctil…** in Director, and the same action beside the catalogue save in the structured interactive creator, prepare three editable deliveries from one frozen source. Horizontal is 1920×1080, vertical 1080×1920, and touch 768×1024. Horizontal/vertical keep the creation's output type; touch is always interactive. Director projects originating from the interactive creator remain interactive in every format. Native structured projects retain their scene and navigation model and native editor kind.

Each variant receives its own Stage dimensions, source project, rendered artifact, and format identifier under `plan.admiraPackage`. Montage coordinates remain proportional to the format and timeline/actions are copied unchanged. This does not automatically redesign a composition for a new aspect ratio: the author must review the framing. Video variants are separate recordings at their actual pixel dimensions, rather than one recording shown in different viewports. The recorder uses an offscreen Studio iframe whose storage is replaced with an isolated in-memory copy before editor scripts execute; the author's plan, storage, Stage and timeline are not used as a temporary export workspace. Native interactives use their existing responsive HTML player. Package Director HTML uses the frozen package timeline and FPS rather than the open workspace's transport duration.

Every resource and action is checked before preparation. Each unsaved delivery then requires its own sandboxed preview and explicit approval. Preview uses the exact Blob/HTML subsequently uploaded. A changed workspace, bad resource/action, failed build, player error, or unavailable recovery storage blocks publication. Preparation can be cancelled. The original editable creation remains open throughout.

The package and its artifacts are stored in IndexedDB before publication. Its history is local to this browser and can recover older completed or pending packages, including after a reload. New packages retain previous history. Each published resource has a common `paquete-<uuid>` catalogue tag, a format tag, a labelled title and its editable source; existing parent/return context is preserved. The manifest download records the package identity, format dimensions, per-delivery state and confirmed catalogue/source links. All three catalogue links remain in the editor after success.

Publication is sequential, with a persisted `sending` state before each request and a receipt after it. Web Locks prevent simultaneous sends of the same package from different tabs. A definite 4xx rejection can be retried after correction; confirmed deliveries are skipped. A timeout, lost response or malformed receipt stays uncertain: recovery checks the complete catalogue for exactly one resource carrying the package and format tags, and never blindly repeats the request. If that cannot establish the outcome, publication stops and asks the author to check the catalogue. There is no server-side all-or-nothing transaction: a partial package is shown as partial and its confirmed resources remain available. Pending deliveries require review again after reload. The same browser's stored files are needed to resume; the downloadable manifest is a receipt, not a media backup.

Validation: 11 package unit cases cover preservation, all three output modes, native structured sources, resource/action failures, cancellation, journal ordering, partial publication/reconciliation, ambiguous outcomes, stale sources and storage failure. Nine headless browser scenarios record real horizontal/vertical videos containing a generated image and text, verify decoded dimensions and unchanged author storage/Stage, exercise a real touch action, require all three approvals, recover a rejected vertical delivery after reload without republishing horizontal, validate the manifest, reject a stale source and bad media/actions, and prepare native structured versions with real touch navigation. These tests intercept catalogue writes. All 266 unit tests in the non-browser suite pass; the existing nine preflight and seven resource-update browser scenarios also pass.

Run `PLAYWRIGHT_BROWSER_CHANNEL=chrome npm run verify:admira-format-package`. Screenshots default to `/tmp/ainimation-format-package` (`FORMAT_PACKAGE_ARTIFACT_DIR` overrides it). Release requires only AInimation. Actual temporary publication of the three variants, catalogue metadata/source retrieval, and cleanup remain production release checks.
