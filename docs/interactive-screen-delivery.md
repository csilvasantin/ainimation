# Enviar un interactivo a una pantalla de Xpacio

Desde el Creador: conectar Google, abrir el proyecto y pulsar **Enviar a Xpacio**. Elegir Starbucks · Paseo de Gracia 103 y una pantalla con capacidad táctil confirmada (tótem táctil o iPad horizontal). El previo muestra la versión guardada. **Preparar envío** conserva esa versión de forma independiente; **Abrir en admira.store** muestra su revisión antes de aplicarla. **Mostrar en esta pantalla** la coloca sólo en el destino elegido, **Abrir pantalla** la amplía y **Restaurar pantalla** retira la capa conservando la programación subyacente. Los enlaces de entrega permiten a quien los tenga reproducir la versión; no incluyen credenciales Google ni la identidad del propietario. Editar el proyecto no cambia una entrega anterior: preparar otro envío crea la nueva versión.

English: connect Google, open a project, choose **Send to Xpace**, Starbucks and a confirmed touch screen. **Prepare delivery** creates an immutable copy; **Open in admira.store** reviews it before **Show on this screen**. **Open screen** enlarges it; **Restore screen** removes the layer without editing playlists. Link holders can view the snapshot. Later edits need another delivery. Previous projects remain unchanged.

Current scope: two confirmed virtual touch destinations (totem and landscape iPad) in the Starbucks twin. Other Xpaces and physical-player publication are not connected by this feature. Existing remote playlists, physical queues and fleet commands are unchanged. A D1 write is not a physical playback acknowledgement. Technical contract and bilingual Store usage: `https://www.admira.store/admira-xp/docs/ainimation-screen-delivery.md`.

The existing library Worker verifies Google for `GET /api/destinations` and `POST /api/deliveries`. Snapshots use a separate `interactive_deliveries` table; no project record is updated. Creation is idempotent for owner + source project/revision + content hash + destination. The unlisted 64-hex ID reads metadata or its `/player` HTML. CORS from Store applies only to these public delivery reads; it grants no access to the project API. The receiver checks the fixed API/player origin, location and screen, and uses script-only sandboxed iframes with no referrer.

Wrangler must keep `keep_names = false`: the HTML exporter serializes its runtime with `toString()`, and esbuild's default `__name` helper is not present in the exported browser page. Check the emitted Worker with `node cloud-library/scripts/check-delivery-bundle.mjs <bundle>/preview-worker.js` after building/deploying with an output directory. This regression was found in the real Chrome receipt test, then verified against the actual emitted bundle.

Validation before touch restriction: 61 interactive tests; three Store receiver/preservation tests plus existing playback/light/display checks. Real Google created a demo snapshot in preview; Chrome displayed it on virtual Pantalla 1, navigated the coffee selection and product, and restored the prior surface. Broad MCP tests have 15 pre-existing failures in both the unmodified base and updated tree, with zero new failures; the new bilingual help and existing native/Matrix contracts pass their focused tests. Production verification is recorded after coordinated publication.

Touch restriction / Restricción táctil (21 October 2026): only `touch === true` is selectable and accepted by the save API. Wall and POS displays are excluded; unknown capability fails closed. The Store receiver independently restricts IDs and requires confirmed touch metadata. When a selected Xpace has none, show «Este Xpacio no tiene pantallas táctiles disponibles» / “This Xpace has no touch screens available”, with selection and submission disabled. Focused and regression checks: 64 interactive tests plus four receiver tests and one MCP help test pass.
